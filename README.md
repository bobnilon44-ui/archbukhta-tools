# АрхБухта — касса самообслуживания для инструментов

Офлайн-приложение для ноутбука с камерой в комнате с инструментами. Дежурного нет: участники сами берут
и возвращают инструмент, сканируя QR-коды. Интернет не нужен ни для работы, ни для печати QR.

## Запуск

1. Скопируйте папку проекта на ноутбук.
2. Запустите `start.bat` (Windows) или `./start.sh` (macOS/Linux). Скрипт поднимет локальный сервер
   на `http://localhost:8080` и откроет браузер (лучше Chrome или Edge).
   Для сервера нужен **Node.js** или **Python 3**: подойдёт любой, что уже установлен.
3. Разрешите доступ к камере. Нажмите на экран: включатся звук и полноэкранный режим.

> **Важно:** всегда открывайте приложение по одному и тому же адресу `http://localhost:8080`.
> База хранится в браузере и привязана к адресу: на другом порту или в другом браузере она будет пустой.
> После первого открытия приложение кэшируется и запускается даже без сервера.

## Первая настройка (админка: ⚙ в углу кассы, PIN по умолчанию `0000`)

1. **Настройки:** смените PIN. Для пробы можно нажать «Загрузить демо-данные».
2. **Команды:** вставьте список команд, по одной на строку, и нажмите «Добавить и сделать бейджи».
   Откроется страница печати бейджей.
3. **Инвентарь и QR:** создайте типы, например «Циркулярная пила», 4 шт.; «Аккумулятор 18V», вид «аккумулятор», 10 шт.
   Коды единиц (`TSIRPIL-01`, `TSIRPIL-02`, …) и их QR **генерируются автоматически и офлайн**.
4. **Расходники:** добавьте саморезы и другие расходники с начальным остатком.
5. Напечатайте QR: «Печать / сохранить PDF», в окне печати выберите «Сохранить как PDF», масштаб 100%.
   Ламинируйте. Перед печатью всей партии проверьте пару кодов на кассе.

### Добавление нового оборудования во время конкурса
«Инвентарь и QR» → в строке типа укажите количество и нажмите «+». Если тип новый, заполните форму «Добавить новый тип».
Сразу появится кнопка **«Печать QR для новых»**: печатаются только только что добавленные единицы.

## Как пользоваться кассой

**Взять:** бейдж команды → QR каждого инструмента или аккумулятора → «Далее» → расходники
(нажать, ввести количество) или «Без расходников — выдать».

**Вернуть:** QR инструмента → «Вернуть». Бейдж не нужен: инструмент снимается с той команды, за которой числится.
Для аккумулятора выводится крупное напоминание **«Поставьте аккумулятор на зарядку!»**.

**Передача между командами** только через комнату: сначала возврат, потом новая выдача.
Пока инструмент не вернули, другая команда взять его не сможет.

Защита от ошибок:
- нельзя выдать то, что уже выдано, и вернуть то, что не выдано;
- повторный скан того же кода в течение 2,5 с игнорируется;
- **лимит**: по умолчанию 2 единицы одного типа на команду, для аккумуляторов 4. Лимит меняется для каждого типа
  в «Инвентаре» (0 = без лимита). Проверка учитывает и то, что уже на руках, и то, что лежит в корзине.
  При превышении появляется сообщение «Лимит для вашей команды: 2 шт. Сначала верните один». На расходники лимит не действует;
- выдача атомарна: если что-то не прошло проверку, не выдаётся ничего;
- корзина сама отменяется через 60 с бездействия (настраивается), чтобы следующий человек не выдал инструмент на чужую команду;
- зелёная вспышка и сигнал означают успех, красная и низкий сигнал — ошибку, жёлтая — предупреждение;
- если QR повреждён, есть кнопка «Ввести код вручную». USB-сканер QR тоже работает, в том числе при русской раскладке.

## Админка

| Вкладка | Что там |
|---|---|
| **На руках** | Кто что держит прямо сейчас, сколько времени. «Вернуть» без скана: причина пишется в журнал |
| **Итоги** | Отчёт для конца конкурса: кто не вернул; по каждому типу сколько всего, в комнате и у кого; что каждая команда брала; расходники (поступило, выдано, остаток, по командам). Печать/PDF и CSV |
| **Журнал** | Все операции с поиском и фильтром |
| **Инвентарь и QR** | Типы, лимиты, единицы, статусы (обслуживание, списан), печать QR |
| **Команды** | Добавление, переименование, отключение, бейджи |
| **Расходники** | Остатки, пополнение, инвентаризация (задать факт), порог «на исходе» |
| **Настройки** | PIN, лимиты по умолчанию, тайм-аут, звук, резервная копия, демо, очистка |

CSV сохраняются с разделителем `;` в UTF-8 с BOM, поэтому русский Excel открывает их двойным кликом.

## Резервная копия

Данные лежат в браузере ноутбука (IndexedDB). **Регулярно** нажимайте «Скачать копию (JSON)» и сохраняйте её на флешку
или, когда есть интернет, в облако. Если копия давно не делалась, вкладка «На руках» напомнит об этом.
Этим же файлом можно перенести базу на другой компьютер: подготовить команды и инвентарь заранее, затем «Восстановить из файла».

## Структура

```
app/                  PWA (корень сайта)
  index.html          касса
  admin.html          админка
  labels.html         печать QR (бейджи, наклейки 60/45/32 мм) → PDF через печать браузера
  sw.js               офлайн-кэш
  js/db.js            IndexedDB: схема, транзакции
  js/logic.js         бизнес-логика без DOM: выдача, возврат, лимиты, отчёты, CSV
  js/scanner.js       камера + jsQR, USB-сканер, антидребезг
  js/kiosk.js         экран кассы (конечный автомат)
  js/admin.js         админка
  vendor/             jsQR (распознавание) и qrcode-generator (генерация): локально, без CDN
server.js             мини-сервер без зависимостей
tests/                тесты логики (node --test + fake-indexeddb)
```

### Схема данных (IndexedDB `archbukhta-tools`)

| Хранилище | Поля |
|---|---|
| `teams` | `id` (T01…), `name`, `active` |
| `toolTypes` | `id` (код типа, напр. TSIRPIL), `name`, `kind` (`tool`/`battery`), `limit` (0 = без лимита) |
| `items` | `id` (TSIRPIL-01 — он же в QR), `typeId`, `label`, `status` (`in`/`out`/`service`/`retired`), `holderTeamId`, `issuedAt` |
| `consumables` | `id` (C01…), `name`, `unit`, `stock`, `lowThreshold` |
| `operations` | журнал (только добавление): `ts`, `op` (`issue`/`return`/`override`/`consume`/`restock`/`adjust`/`register`/`status`), команда, предмет/расходник, `qty`, `note`, `synced` |
| `settings` | `adminPin`, `defaultLimit`, `batteryLimit`, `cartTimeoutSec`, `soundOn`, `eventName`, `lastBackupAt` |

Формат QR: `AB:T:<команда>`, `AB:I:<инструмент>`, `AB:C:<расходник>`.
